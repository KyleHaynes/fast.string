3  Clean and standardise text

Most matching problems are really cleaning problems. Two records for the same business rarely differ by a typo; they differ by &amp; against &, St. against Street, Müller against Mueller, or a postcode that lost its leading zero on the way through a spreadsheet. This chapter collects the functions that remove that noise, each of them one vectorised, multi-core call.

Task Function Instead of
Decode &amp;, &eacute;, &#8211; html_unescape() xml2 one string at a time, or nothing
Decode %20, + in URLs and query strings url_decode() utils::URLdecode() (R code, per string)

3.1 Web residue: entities, escapes and odd spaces

Text that has passed through a web page, a CMS export or a JSON API often arrives with HTML character references still in it, and with non-breaking or ideographic spaces where you expect ordinary ones. html_unescape() decodes every named and numeric reference of the HTML standard – exactly as Python’s html.unescape() does – and fsquish() trims and collapses every kind of Unicode whitespace:

scraped <- c("  Caf\u00e9\u00a0Nero ", "Fish &amp; Chips\tCo.",
             "O\u2019Brien &#8211; Plumbing", "M\u00fcller\u3000GmbH",
             "Smith &amp;&nbsp;Sons", "PLAIN NAME")
fsquish(html_unescape(scraped))
[1] "Café Nero"          "Fish & Chips Co."   "O’Brien – Plumbing" "Müller GmbH"        "Smith & Sons"       "PLAIN NAME"

&nbsp; decodes to a non-breaking space, which is why fsquish() runs second. Strings without an & are returned untouched (not even copied), so running html_unescape() over a column that is mostly clean costs almost nothing.

Web logs and exported URLs carry percent-encoding instead. Pull out the part you need with fextract() and decode it; plus = TRUE treats + as a space, as HTML forms encode it:

logs <- c("/search?q=fish+%26+chips&page=2", "/search?q=caf%C3%A9+latte",
          "/search?page=1&q=100%25+beef", "/about")
q <- fextract("[?&]q=([^&]*)", logs, group = 1)
data.frame(q, decoded = url_decode(q, plus = TRUE))
                q      decoded
1  fish+%26+chips fish & chips
2 caf%C3%A9+latte   café latte
3     100%25+beef    100% beef
4            <NA>         <NA>

url_encode() goes the other way, with reserved = TRUE for a single query value. Both agree with utils::URLencode()/URLdecode() – except that a broken escape such as %zz is kept as it is rather than turned into garbage – and are several hundred times faster, because the base functions loop over characters in R code.

3.2 Accents and typographic symbols

Names keyed on different systems disagree about accents: one has François Müller, another Francois Muller. ascii_fold() applies the same Latin-to-ASCII transliteration as ICU (and stringi), including ligatures, Nordic letters and typographic punctuation:

names <- c("Fran\u00e7ois M\u00fcller", "Zo\u00eb \u00c6lfric",
           "Bj\u00f6rk Gu\u00f0mundsd\u00f3ttir", "\u0141\u00f3d\u017a",
           "\u201cQuoted\u201d \u2013 dash", "\u00bd price \u2026")
data.frame(names, folded = ascii_fold(names))
                 names               folded
1      François Müller      Francois Muller
2           Zoë Ælfric          Zoe AElfric
3 Björk Guðmundsdóttir Bjork Gudmundsdottir
4                 Łódź                 Lodz
5      “Quoted” – dash      "Quoted" - dash
6            ½ price …        1/2 price ...

Characters with no ASCII spelling (other scripts, emoji) are kept, or replaced with sub when the output must be pure ASCII:

ascii_fold("Tokyo \u6771\u4eac caf\u00e9", sub = "?")
[1] "Tokyo ?? cafe"

The phonetic codes (soundex(), nysiis() and the rest) already fold accented letters internally; fold explicitly before the similarity functions and before hashing, where é and e would otherwise differ.

3.3 Standardise words with a dictionary

Abbreviations are the biggest single source of disagreement in addresses and organisation names. freplace_tokens() replaces every whitespace- separated token found in a dictionary, in one hashed pass per string. An empty replacement deletes the token, and the result comes back squished. Strip the punctuation that clings to tokens first:

addr <- c("12 Smith St.", "3/45 North Rd", "UNIT 7, 9 KING STREET",
          "Flat 2 18 Queen st", "U 5/22 the Esplanade Hwy")
abbrev <- data.frame(
    from = c("ST", "RD", "AVE", "HWY", "CRES", "PDE", "FLAT", "U"),
    to   = c("STREET", "ROAD", "AVENUE", "HIGHWAY", "CRESCENT", "PARADE",
             "UNIT", "UNIT")
)
std <- freplace_tokens(fgsub("[.,]+", " ", toupper(addr)), abbrev$from, abbrev$to)
data.frame(addr, std)
                      addr                             std
1             12 Smith St.                 12 SMITH STREET
2            3/45 North Rd                 3/45 NORTH ROAD
3    UNIT 7, 9 KING STREET            UNIT 7 9 KING STREET
4       Flat 2 18 Queen st          UNIT 2 18 QUEEN STREET
5 U 5/22 the Esplanade Hwy UNIT 5/22 THE ESPLANADE HIGHWAY

Only whole tokens change – ST becomes STREET, but STAR and STREET itself are left alone – which is what makes a dictionary approach safe where gsub("ST", "STREET", x) is not. Matching can ignore ASCII case, and replacements may contain several words. The same mechanism maps name variants to one canonical form, here a (very) short nickname table:

nick <- data.frame(
    from = c("BILL", "BILLY", "WILL", "BOB", "ROB", "BOBBY", "PEG", "PEGGY",
             "LIZ", "BETH"),
    to   = c("WILLIAM", "WILLIAM", "WILLIAM", "ROBERT", "ROBERT", "ROBERT",
             "MARGARET", "MARGARET", "ELIZABETH", "ELIZABETH")
)
freplace_tokens(c("BILL", "Bob", "peggy", "WILLIAM", "LIZ ANNE"),
                nick$from, nick$to, ignore_case = TRUE)
[1] "WILLIAM"        "ROBERT"         "MARGARET"       "WILLIAM"        "ELIZABETH ANNE"

Dictionaries of thousands of entries cost no more per token than a dictionary of ten, because each token is one hash lookup. The equivalent in base R splits every string into a list, matches and pastes back:

set.seed(1)
n <- 2e5
words <- c("12", "SMITH", "ST", "RD", "AVE", "UNIT", "MR", "DR", "JOHN",
           "NORTH", "QLD", "4000")
x <- vapply(seq_len(n), function(i) paste(sample(words, 5, TRUE), collapse = " "), "")

system.time(freplace_tokens(x, abbrev$from, abbrev$to))
   user  system elapsed 
   0.14    0.02    0.06 
system.time({
    tok <- strsplit(x, " ", fixed = TRUE)
    vapply(tok, function(t) {
        m <- match(t, abbrev$from)
        t[!is.na(m)] <- abbrev$to[m[!is.na(m)]]
        paste(t, collapse = " ")
    }, "")
})
   user  system elapsed 
   1.79    0.14    1.92

3.4 Restore leading zeros

Spreadsheets and CSV readers turn postcodes, phone numbers and identifiers into numbers and silently drop their leading zeros – every Northern Territory postcode (0800-0899) comes back as three digits. fpad() puts them back; side = "right" pads text for fixed-width exports:

fpad(as.character(c(800, 810, 2000, 4000, 870)), 4, pad = "0")
[1] "0800" "0810" "2000" "4000" "0870"
fpad(c("ID", "NAME", "POSTCODE"), 10, side = "right")
[1] "ID        " "NAME      " "POSTCODE  "

Width counts characters, not bytes, so accented text pads correctly too.

3.5 Find the spelling variants

Before matching against anything else, it helps to know how many ways one value is spelled within a column. OpenRefine’s key collision clustering does this with a fingerprint: lower-case, fold accents, remove punctuation, then sort the unique words. Values that share a fingerprint are almost always the same thing:

companies <- c("Acme Pty Ltd", "ACME PTY. LTD.", "Ltd Acme Pty", "acme pty ltd ",
               "Acme Holdings", "Bolt & Nut Co", "Bolt and Nut Co",
               "Bolt & Nut Co.", "Cafe Nero", "Caf\u00e9 Nero")
key <- fingerprint(companies)
clusters <- split(companies, key)
clusters[lengths(clusters) > 1]
$`acme ltd pty`
[1] "Acme Pty Ltd"   "ACME PTY. LTD." "Ltd Acme Pty"   "acme pty ltd " 

$`bolt co nut`
[1] "Bolt & Nut Co"  "Bolt & Nut Co."

$`cafe nero`
[1] "Cafe Nero" "Café Nero"

"Bolt and Nut Co" stays out, because the fingerprint deletes & but keeps and. A dictionary pass first fixes that, which is the general pattern: standardise with freplace_tokens(), then cluster:

key2 <- fingerprint(freplace_tokens(companies, "and", "&", ignore_case = TRUE))
split(companies, key2)[["bolt co nut"]]
[1] "Bolt & Nut Co"   "Bolt and Nut Co" "Bolt & Nut Co."

ngram_fingerprint() sorts the unique character n-grams instead of words, so it also joins values that differ by spacing or transposed letters (n = 1 is the most forgiving):

ngram_fingerprint(c("Cafe Nero", "CafeNero", "Cafe Neor"), n = 1)
[1] "acefnor" "acefnor" "acefnor"

Use the clusters to build the dictionary for freplace_tokens(), or as a deduplication key in their own right.

3.6 A cleaning pipeline

In practice these run as one function applied to each name or address column before blocking and scoring:

clean_name <- function(x) {
    x <- html_unescape(x)
    x <- ascii_fold(x)
    x <- toupper(x)
    x <- fgsub("[^A-Z0-9 ]+", " ", x)
    x <- freplace_tokens(x, c(nick$from, "DR", "MR", "MRS", "MS"),
                         c(nick$to, "", "", "", ""))
    fsquish(x)
}
clean_name(c("  Dr. Fran\u00e7ois  O\u2019Brien-Smith ", "MR&nbsp;BILL  JONES",
             "bob jones"))
[1] "FRANCOIS O BRIEN SMITH" "WILLIAM JONES"          "ROBERT JONES"

Every step is parallel and returns unchanged strings without copying them, so a pipeline like this keeps up with the matching steps that follow (Chapter 6) even at millions of rows.
