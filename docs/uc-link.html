6  Match, deduplicate and link records

Record linkage – finding the records that refer to the same person, business or address, within one file or across several – has the same shape whatever the data:

  1. Standardise the fields you compare (Chapter 3).
  2. Generate candidate pairs cheaply, so that only plausible pairs are compared in detail: blocking, the sorted neighbourhood method, or a similarity search.
  3. Score each candidate pair, field by field.
  4. Decide which pairs are matches.
  5. Cluster the matched pairs into entities.

Chapter 9 walks through a small linkage end to end. This chapter is the toolbox for each stage, and finishes by deduplicating 100,000 records.

6.1 Candidate pairs by blocking

Comparing every record with every other is \(O(n^2)\): five billion pairs for 100,000 records. Blocking only pairs records that agree exactly on a key, such as the Soundex code of the surname plus the date of birth. One key misses every true match with an error in that key, so linkage projects run several passes with different keys and take the union. block_pairs() does that in one call, with one column per pass, and reports each pair once along with the first pass that found it:

people <- data.frame(
    surname  = c("SMITH", "SMYTH", "JONES", "SMITH", "JONSE", "BROWN", "SMITH-JONES"),
    given    = c("JOHN", "JON", "MARY", "JOHN", "MARY", "ROBERT", "MARY"),
    dob      = as.Date(c("1980-01-02", "1980-01-02", "1975-06-30", "1990-12-01",
                         "1975-06-30", "1962-03-03", "1975-03-06")),
    postcode = c("4000", "4000", "2000", "4101", "2000", "3000", "2000")
)
keys <- data.frame(
    surname_dob = paste(soundex(people$surname), people$dob),
    dob         = people$dob,
    initial_pc  = paste(substr(people$given, 1, 1), people$postcode)
)
block_pairs(keys)
  x_index y_index pass
1       1       2    1
2       3       5    1
3       3       7    3
4       5       7    3

Record 7 – Mary Jones after a double-barrelled marriage, with day and month swapped in her date of birth – only shares the third key with records 3 and 5, and the pass column shows it. That makes a blocking design auditable: you can see which pass carries the recall, and drop the ones that only add noise. A missing key (NA) never pairs, and max_block_size skips blocks too big to be useful, such as the most common surname, with a warning.

Linking two files instead of deduplicating one is the same call with a second set of keys: block_pairs(keys_a, keys_b) returns pairs with one record from each.

6.2 The sorted neighbourhood method

Exact keys miss pairs whose keys differ in the last characters (SMITH and SMITHE). sorted_neighbourhood() sorts the distinct key values and pairs records whose values are within (window - 1) / 2 places of each other, as well as records with equal values. A second pass on the reversed key catches errors at the start of the string:

surname <- c("SMITH", "SMITHE", "SMYTH", "JONES", "JONSON", "XMITH")
rev_str <- function(s) vapply(strsplit(s, NULL),
                              function(ch) paste(rev(ch), collapse = ""), "")
p <- sorted_neighbourhood(data.frame(surname, rev_str(surname)), window = 3)
data.frame(a = surname[p$x_index], b = surname[p$y_index], pass = p$pass)
       a      b pass
1  SMITH SMITHE    1
2  SMITH JONSON    1
3  SMITH  XMITH    2
4 SMITHE  SMYTH    1
5  SMYTH JONSON    2
6  SMYTH  XMITH    1
7  JONES JONSON    1

XMITH only meets SMITH in the reversed pass. The window moves over distinct values, as in Python’s recordlinkage package, so the pairs do not depend on the order of the records and every tie is paired. Keys can be dates or numbers too: a date of birth with window = 3 pairs dates one day apart.

6.3 Choose phonetic keys by how much they merge

Every phonetic code merges some spellings and separates others, and the trade-off is block size against recall. Comparing codes on a list of known variants shows the differences quickly:

surn <- c("SMITH", "SMYTH", "SCHMIDT", "MEYER", "MEIER", "MCDONALD",
          "MACDONALD", "THOMPSON", "TOMSON", "NGUYEN", "NGYUEN", "PHILLIPS",
          "FILLIPS")
codes <- data.frame(name = surn, soundex = soundex(surn), nysiis = nysiis(surn),
                    metaphone = metaphone(surn), statcan = statcan(surn),

                    mra = mra_encode(surn))

Soundex merges SCHMIDT with SMITH but separates PHILLIPS from FILLIPS; Phonex and ONCA join the latter pair; NYSIIS and Metaphone separate more spellings, which makes smaller blocks and needs more passes. The Match Rating Approach is designed as a comparison rather than a key: mra_compare() says whether two names match under its rules.

mra_compare(c("SMITH", "BYRNE", "CATHERINE"), c("SMYTH", "BOERN", "KATHRYN"))

6.4 Candidates without blocking keys

When there is no good key, search for similar strings directly; none of these functions builds the full comparison matrix.

fuzzy_within() returns every table entry within k edits of each query, using SymSpell’s symmetric-delete index – the right tool for checking typed values against a reference list such as a street gazetteer:

set.seed(7)
streets <- unique(paste(
    sample(c("KING", "QUEEN", "GEORGE", "ELIZABETH", "ANN", "ADELAIDE", "WICKHAM",
             "BRUNSWICK", "LOGAN", "IPSWICH", "OXLEY", "SANDGATE", "GYMPIE",
             "STANLEY", "MAIN", "CHURCH", "STATION", "RIVER"), 4000, TRUE),
    sample(c("ST", "RD", "AVE", "TCE", "PDE", "LANE", "CT", "CRES"), 4000, TRUE)
))
q <- c("KIGN ST", "QUEEN SRT", "WICKAM TCE", "LOGAN RD")
w <- fuzzy_within(q, streets, max_distance = 2)
data.frame(query = q[w$query_index], match = streets[w$table_index],
           distance = w$distance)
        query       match distance
1     KIGN ST     KING ST        1
2     KIGN ST     KING CT        2
3   QUEEN SRT    QUEEN ST        1
4   QUEEN SRT    QUEEN CT        2
5   QUEEN SRT    QUEEN RD        2
6  WICKAM TCE WICKHAM TCE        1
7    LOGAN RD    LOGAN RD        0
8    LOGAN RD   LOGAN PDE        2
9    LOGAN RD    LOGAN ST        2
10   LOGAN RD    LOGAN CT        2

Results come ordered by distance, so the first row per query is the best. The result is exact – the same pairs as filtering a full osa_distance_matrix() – at a fraction of the cost for large tables.

For names that differ by whole words – organisations with and without THE, UNI for UNIVERSITY, an extra department – edit distance is the wrong measure. tfidf_match() compares TF-IDF-weighted character n-grams, so rare, informative words dominate and common ones barely count:

orgs <- c("UNIVERSITY OF QUEENSLAND", "QUEENSLAND UNIVERSITY OF TECHNOLOGY",
          "GRIFFITH UNIVERSITY", "QUEENSLAND HEALTH", "BRISBANE CITY COUNCIL",
          "LOGAN CITY COUNCIL", "UNIVERSITY OF SYDNEY")
qs <- c("THE UNIVERSITY OF QUEENSLAND", "QLD UNIVERSITY OF TECHNOLOGY",
        "BRISBANE CITY COUNCIL LIBRARIES", "GRIFFITH UNI", "SYDNEY UNIVERSITY")
data.frame(query = qs, match = orgs[tfidf_match(qs, orgs)])
                            query                               match
1    THE UNIVERSITY OF QUEENSLAND            UNIVERSITY OF QUEENSLAND
2    QLD UNIVERSITY OF TECHNOLOGY QUEENSLAND UNIVERSITY OF TECHNOLOGY
3 BRISBANE CITY COUNCIL LIBRARIES               BRISBANE CITY COUNCIL
4                    GRIFFITH UNI                 GRIFFITH UNIVERSITY
5               SYDNEY UNIVERSITY                UNIVERSITY OF SYDNEY
tfidf_top_n("QLD UNIVERSITY OF TECHNOLOGY", orgs, top_n = 3)
  query_index table_index     score rank
1           1           2 0.8001508    1
2           1           7 0.3253862    2
3           1           1 0.3249688    3

For long text – product descriptions, case notes, addresses with free-text additions – minhash_pairs() finds pairs whose q-gram sets probably overlap by at least threshold (Jaccard), using locality-sensitive hashing, and verifies each candidate exactly:

descr <- c("Stainless steel kettle 1.7 litre with auto shut-off and boil-dry protection",
           "Stainless steel kettle 1.7L with auto shut off and boil dry protection",
           "Cordless stick vacuum cleaner with HEPA filter and wall mount",
           "Cordless stick vacuum with HEPA filter, wall mount included",
           "Cast iron frying pan 28cm pre-seasoned")
minhash_pairs(descr, threshold = 0.4)
  x_index y_index   jaccard
1       1       2 0.7195122
2       3       4 0.6197183

6.5 Score with the comparison that fits the field

Jaro-Winkler is the standard for short names, but each kind of field has its own kind of difference:

  • Phonetic misspellings (PH/F, C/K) cost less under editex(), an edit distance whose substitution cost depends on whether the letters sound alike:

    a <- c("PHILIP", "CATHERINE", "SHEPHERD")
b <- c("FILIP", "KATHRYN", "SHEPPARD")
data.frame(a, b, levenshtein = levenshtein_similarity(a, b),
           editex = editex_similarity(a, b))
              a        b levenshtein    editex
1    PHILIP    FILIP   0.6666667 0.7500000
2 CATHERINE  KATHRYN   0.5555556 0.7222222
3  SHEPHERD SHEPPARD   0.7500000 0.8125000

  • Multi-word names with reordered, missing or extra words suit monge_elkan() (the mean best match of each word) or jaro_winkler_tokens():

    a <- c("JOHN PAUL SMITH", "MARY JANE O BRIEN", "ROBERT JONES")
b <- c("SMITH JOHN", "OBRIEN MARY", "BOB JONES")
data.frame(a, b, jaro_winkler = jaro_winkler(a, b),
           monge_elkan = monge_elkan(a, b), tokens = jaro_winkler_tokens(a, b))
                      a           b jaro_winkler monge_elkan    tokens
1   JOHN PAUL SMITH  SMITH JOHN    0.5000000   0.6666667 0.6666667
2 MARY JANE O BRIEN OBRIEN MARY    0.5659537   0.7986111 0.5666667
3      ROBERT JONES   BOB JONES    0.7060185   0.7888889 0.7500000

  • One string inside another – a street address inside a full address line – is local alignment: smith_waterman() scores the best-matching substring, and lcs_str() returns the longest common substring:

    smith_waterman(c("9 KING ST", "9 KING ST"),
               c("UNIT 4 9 KING ST BRISBANE", "19 KINGS ST"))
    [1] 1.0000000 0.9444444
    lcs_str("9 KING ST", "UNIT 4 9 KING ST BRISBANE")
    [1] "9 KING ST"

When a pair goes to clerical review, edit_ops() explains a distance as the edits themselves:

edit_ops("JONATHAN", "JONHATAN", type = "opcodes")
  pair   type a_start a_end b_start b_end
1    1  equal       1     3       1     3
2    1 insert       4     3       4     4
3    1  equal       4     5       5     6
4    1 delete       6     6       7     6
5    1  equal       7     8       7     8

6.6 From matched pairs to entities

Deduplication needs one identifier per entity, not a list of pairs. cluster_pairs() joins records connected by any chain of matches (the connected components of the match graph):

# 1 matches 2, 2 matches 3, 4 matches 5; record 6 matches nothing
cluster_pairs(c(1, 2, 4), c(2, 3, 5), n = 6)
[1] 1 1 1 2 2 3

Chaining is also the risk: if 1 and 3 do not match directly, the cluster rests on record 2. Look at the largest clusters before trusting them, or raise the threshold for pairs that join large clusters.

6.7 End to end: deduplicating 100,000 records

To see the whole pipeline at a useful scale, build a file of 80,000 people in which a quarter appear a second time with one error each: a typo in the surname or given name, a date of birth one day out, or a missing postcode.

set.seed(42)
surnames <- c("SMITH", "JONES", "WILLIAMS", "BROWN", "WILSON", "TAYLOR", "JOHNSON",
    "WHITE", "MARTIN", "ANDERSON", "THOMPSON", "NGUYEN", "THOMAS", "WALKER", "HARRIS",
    "LEE", "RYAN", "ROBINSON", "KELLY", "KING", "DAVIS", "WRIGHT", "EVANS", "ROBERTS",
    "GREEN", "HALL", "WOOD", "JACKSON", "CLARKE", "PATEL", "KHAN", "LEWIS", "JAMES",
    "PHILLIPS", "MITCHELL", "CAMPBELL", "MORRIS", "YOUNG", "SCOTT", "MURPHY", "COOK",
    "BAKER", "TURNER", "COOPER", "HILL", "WARD", "HUGHES", "MOORE", "CHEN", "WANG",
    "SINGH", "OBRIEN", "MCDONALD", "STEWART", "MACDONALD", "SULLIVAN", "MURRAY",
    "WATSON", "PRICE", "BELL", "ALLEN")
given <- c("JOHN", "MARY", "ROBERT", "JENNIFER", "MICHAEL", "LINDA", "WILLIAM",
    "ELIZABETH", "DAVID", "SUSAN", "JAMES", "MARGARET", "PETER", "SARAH", "ANDREW",
    "JESSICA", "DANIEL", "EMILY", "MATTHEW", "CHLOE", "THOMAS", "OLIVIA", "JOSHUA",
    "EMMA", "RYAN", "GRACE", "BENJAMIN", "SOPHIE", "LUKE", "HANNAH", "KYLE", "ZOE",
    "NATHAN", "AMY", "SAMUEL", "LUCY")
n_people <- 80000
truth <- data.frame(
    person   = seq_len(n_people),
    surname  = sample(surnames, n_people, TRUE),
    given    = sample(given, n_people, TRUE),
    dob      = as.Date("1940-01-01") + sample(0:25000, n_people, TRUE),
    postcode = sprintf("%04d", sample(c(800:899, 2000:4999), n_people, TRUE))
)

# One random substitution, deletion or transposition per string
typo <- function(s) {
    k <- nchar(s)
    i <- floor(runif(length(s)) * k) + 1
    r <- runif(length(s))
    out <- s
    sub_ <- r < 0.4
    substr(out[sub_], i[sub_], i[sub_]) <- sample(LETTERS, sum(sub_), TRUE)
    del <- r >= 0.4 & r < 0.7
    out[del] <- paste0(substr(s[del], 1, i[del] - 1), substr(s[del], i[del] + 1, 100))
    tr <- r >= 0.7 & i < k
    out[tr] <- paste0(substr(s[tr], 1, i[tr] - 1), substr(s[tr], i[tr] + 1, i[tr] + 1),
                      substr(s[tr], i[tr], i[tr]), substr(s[tr], i[tr] + 2, 100))
    out
}
copies <- truth[sample(n_people, n_people / 4), ]
e <- runif(nrow(copies))
copies$surname[e < 0.3] <- typo(copies$surname[e < 0.3])
copies$given[e >= 0.3 & e < 0.5] <- typo(copies$given[e >= 0.3 & e < 0.5])
off <- e >= 0.5 & e < 0.65
copies$dob[off] <- copies$dob[off] + sample(c(-1, 1), sum(off), TRUE)
copies$postcode[e >= 0.65 & e < 0.8] <- NA

records <- rbind(truth, copies)
records <- records[sample(nrow(records)), ]
nrow(records)
[1] 100000

Three blocking passes, each robust to a different kind of error: a phonetic surname with the date of birth (survives most surname typos), the given name with the date of birth (survives any surname change), and the exact names with the postcode (survives date errors):

system.time(
    pairs <- block_pairs(data.frame(
        surname_dob = paste(soundex(records$surname), records$dob),
        given_dob   = paste(records$given, records$dob),
        names_pc    = paste(records$surname, substr(records$given, 1, 1),
                            records$postcode)
    ))
)
   user  system elapsed 
   0.39    0.11    0.48 
nrow(pairs)

table(pass = pairs$pass)
pass

Score each candidate on every field, weight them, and keep pairs above a threshold:

system.time({
    i <- pairs$x_index
    j <- pairs$y_index
    surname_sim <- jaro_winkler(records$surname[i], records$surname[j])
    given_sim   <- jaro_winkler(records$given[i], records$given[j])
    dob_agree   <- as.numeric(abs(records$dob[i] - records$dob[j]) <= 1)
    pc_agree    <- ifelse(is.na(records$postcode[i]) | is.na(records$postcode[j]), 0.5,
                          as.numeric(records$postcode[i] == records$postcode[j]))
    pairs$score <- (2 * surname_sim + given_sim + dob_agree + 0.5 * pc_agree) / 4.5
})
   user  system elapsed 
      0       0       0 
matches <- pairs[pairs$score >= 0.9, ]

Then cluster the matches into entities:

system.time(entity <- cluster_pairs(matches, n = nrow(records)))

      0       0       0 
c(entities = max(entity), true_people = n_people)

Because the data are synthetic we know the truth, so we can measure how well each stage did:

same_person <- function(a, b) records$person[a] == records$person[b]
true_pairs  <- sum(choose(table(records$person), 2))
c(
    blocking_recall = sum(same_person(pairs$x_index, pairs$y_index)) / true_pairs,
    precision       = mean(same_person(matches$x_index, matches$y_index)),
    recall          = sum(same_person(matches$x_index, matches$y_index)) / true_pairs
)
blocking_recall       precision          recall 
      1.0000000       0.9997996       0.9976000

Blocking reduced five billion possible pairs to a few tens of thousands without losing a true match, and the whole run takes well under a second. The weights and threshold here are picked by hand; on real data, tune them against a labelled sample, or estimate them with a probabilistic model (the fastLink and reclin2 packages fit Fellegi-Sunter weights) and use fast.string for the steps around it.
