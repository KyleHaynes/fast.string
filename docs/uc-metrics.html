7  Choose a string metric

This package ships around thirty ways to score how alike two strings are. Picking one by reputation – “Jaro-Winkler is the standard for names” – leaves the obvious question unanswered: standard for which names, against which wrong answers?

This chapter answers it by measurement. Three hand-labelled sets of pairs, one each for given names, surnames and addresses, are scored by every candidate comparator, and the results say which comparator separates the true pairs from the false ones in each field. Every number below is computed when this page is rendered; the code is all here, so the same exercise runs on your own labelled pairs by swapping the data in.

Three things fall out of it, and they are worth stating before the tables:

  1. The field matters more than the metric’s reputation. The comparator that wins on addresses is near the bottom on given names, and vice versa.
  2. Jaro-Winkler’s prefix bonus is a liability when the wrong answers share a prefix – ALAN/ALANA, HARRIS/HARRISON, 12 SMITH ST/12 SMITH AVE. Plain Jaro, or a length-sensitive edit similarity, discriminates better on exactly the pairs that cause trouble.
  3. For the hardest pairs no comparator works, because the strings do not carry the answer: BOB and ROBERT are the same person and SIMON and SIMONE are not, and no function of two character vectors can know that. Those pairs are fixed by standardising before scoring, by comparing parsed components, or by another field – never by a better metric. sec-recipe does all three.

7.1 The candidates

Comparator Call What it rewards
Jaro-Winkler jaro_winkler(a, b) character agreement, with a bonus for a shared prefix
Jaro jaro_winkler(a, b, p = 0) the same, with no prefix bonus
Jaro-Winkler, tokens jaro_winkler_tokens(a, b) the best alignment of whole words, in any order

OSA osa_similarity(a, b) the same, counting an adjacent swap as one edit

LCS (subsequence) lcs_seq_similarity(a, b) a long common subsequence

Smith-Waterman smith_waterman(a, b) the best-matching local region, gaps forgiven

Cosine, 3-grams cosine_similarity(a, b, q = 3) shared 3-grams, weighted by how often each occurs
Tversky containment tversky_index(a, b, q = 3, alpha = 1, beta = 0) how much of a appears in b, ignoring extra material in b

    osa            = function(a, b) osa_similarity(a, b),
    editex         = function(a, b) editex_similarity(a, b),
    indel          = function(a, b) indel_similarity(a, b),
    lcs_seq        = function(a, b) lcs_seq_similarity(a, b),
    lcs_str        = function(a, b) lcs_str_similarity(a, b),
    prefix         = function(a, b) prefix_similarity(a, b),
    smith_waterman = function(a, b) smith_waterman(a, b),
    jaccard_q2     = function(a, b) jaccard_index(a, b, q = 2),
    jaccard_q3     = function(a, b) jaccard_index(a, b, q = 3),
    cosine_q3      = function(a, b) cosine_similarity(a, b, q = 3),
    tversky_in     = function(a, b) tversky_index(a, b, q = 3, alpha = 1, beta = 0),
    fuzz_token_set = function(a, b) fuzz_token_set_ratio(a, b) / 100,
    fuzz_wratio    = function(a, b) fuzz_wratio(a, b) / 100,
    soundex_equal  = function(a, b) as.numeric(soundex(a) == soundex(b))
)

Every one is put on the same scale, where 1 means identical: the *_similarity() functions already are, the RapidFuzz scorers are divided by 100, and distances are left out in favour of their similarity twins. rLink() does this conversion itself, so a comparator chosen here drops straight into a linkage (sec-uc-link).

for (nm in c("given", "surname", "address")) {
    d <- get(nm)
    d$match <- as.logical(d$match)
    d$degree <- factor(d$degree, levels = c("easy", "moderate", "hard"))
    assign(nm, d)
}

The labels encode one judgement: would a reviewer, seeing only this field, call these the same person or address? Several pairs are genuinely arguable – THOMSON/THOMPSON is a misspelling as often as it is two families – and they are labelled non-match deliberately, because a comparator that cannot be told to be cautious there is a comparator that will merge two people. The non-match side is adversarial by design: half of it is near misses, where a real linkage would see mostly unrelated pairs. The absolute numbers below are therefore pessimistic; what they are good for is ranking the comparators against each other on the pairs that decide a linkage.

7.3 How each comparator is scored

Two measures, both reported per field:

  • AUC – the probability that a randomly chosen true pair outranks a randomly chosen false one, over the easy and moderate pairs only. It needs no threshold, which matters because the right threshold differs per comparator. The hard pairs are excluded here and reported separately, since (as the tables show) no comparator separates them and including them only compresses the ranking.
  • Mean score per cell of the match x degree grid, which is where the behaviour actually shows: a comparator is useful when its moderate matches sit well above its moderate non-matches.
score_all <- function(pairs) {
    scores <- lapply(comparators, function(f) f(pairs$a, pairs$b))
    cbind(pairs, as.data.frame(scores))
}

# Mann-Whitney / rank formulation: no bootstrapping, no ties problem
auc <- function(score, match) {
    r <- rank(score)
    n1 <- sum(match)
    n0 <- sum(!match)
    (sum(r[match]) - n1 * (n1 + 1) / 2) / (n1 * n0)
}

report <- function(pairs) {
    scored <- score_all(pairs)
    easy_mod <- scored$degree != "hard"
    cell <- function(v, keep) round(mean(v[keep]), 2)
    out <- do.call(rbind, lapply(names(comparators), function(nm) {
        v <- scored[[nm]]
        data.frame(
            comparator = nm,
            auc = round(auc(v[easy_mod], scored$match[easy_mod]), 2),
            tp_easy = cell(v, scored$match & scored$degree == "easy"),
            tp_mod  = cell(v, scored$match & scored$degree == "moderate"),
            tp_hard = cell(v, scored$match & scored$degree == "hard"),
            fp_easy = cell(v, !scored$match & scored$degree == "easy"),
            fp_mod  = cell(v, !scored$match & scored$degree == "moderate"),
            fp_hard = cell(v, !scored$match & scored$degree == "hard")
        )
    }))
    out$margin <- out$tp_mod - out$fp_mod
    out[order(-out$auc, -out$margin), ]
}

kable_report <- function(pairs, caption) {
    knitr::kable(
        report(pairs), row.names = FALSE, caption = caption,
        col.names = c("Comparator", "AUC", "easy", "moderate", "hard",
                      "easy", "moderate", "hard", "margin")
    )
}

In the tables, the first group of three columns is the mean score on true matches of each difficulty, the second group the mean on non-matches, and margin is the moderate gap between them – the headroom a threshold has to work in.

7.4 Given names

kable_report(given, NULL)

The ordering is emphatic, and it is the opposite of the folklore. The length-sensitive edit similarities – levenshtein_similarity(), osa_similarity(), lcs_seq_similarity() – separate these names almost perfectly, while jaro_winkler() lands tenth of nineteen with a negative margin: its moderate non-matches score higher (0.89) than its moderate matches (0.88).

The reason is in the prefix row, and in the data. Every moderate non-match here (JOHN/JOHNATHAN, KIM/KIMBERLEY, SAM/SAMUEL) is a longer name that starts with the shorter one, and most of the hard non-matches (ALAN/ALANA, SIMON/SIMONE, MARTIN/MARTINA) are the same thing with one letter. Jaro-Winkler is built to reward a shared prefix, so it rewards precisely the wrong pairs. Turning the bonus off recovers much of the loss:

confusable <- data.frame(
    a = c("ALAN", "SIMON", "MARTIN", "JOHN", "KIM", "DANIEL"),
    b = c("ALANA", "SIMONE", "MARTINA", "JOHNATHAN", "KIMBERLEY", "DANIELLE")
)
data.frame(
    confusable,
    jaro_winkler = round(jaro_winkler(confusable$a, confusable$b), 2),
    jaro         = round(jaro_winkler(confusable$a, confusable$b, p = 0), 2),
    osa          = round(osa_similarity(confusable$a, confusable$b), 2)
)
       a         b jaro_winkler jaro  osa
1   ALAN     ALANA         0.96 0.93 0.80
2  SIMON    SIMONE         0.97 0.94 0.83
3 MARTIN   MARTINA         0.97 0.95 0.86
4   JOHN JOHNATHAN         0.89 0.81 0.44
5    KIM KIMBERLEY         0.84 0.78 0.33
6 DANIEL  DANIELLE         0.95 0.92 0.75

p is tunable rather than all-or-nothing: 0 gives plain Jaro, 0.25 the maximum bonus. If your true matches are typos near the start of the string – common with scanned or dictated data – keep the bonus. If your hard non-matches are suffix extensions, as above, drop it.

The easy column shows what is uncontroversial: every comparator in the table scores an easy match above 0.4 and an unrelated pair below 0.2, so for clean data with only keystroke noise the choice hardly matters. It starts mattering at tp_mod, and by tp_hard the question has changed entirely.

What no comparator can do

Look along the hard row. The best tp_hard figures belong to comparators that also score hard non-matches high, which is no use. The honest reading is that the hard matches here are not a string problem at all:

The one row that stays low is MARY JANE/JANE MARY, which is not a vocabulary problem but a word-order one – and that is a metric choice after all: jaro_winkler_tokens() scores it 1, as the table above shows. A nickname table also has a cost: SAM = "SAMANTHA" fixes one row here and would wrongly merge SAM/SAMUEL, so the table belongs with the rest of your standardisation rules, under review, not buried in a scoring call.

7.5 Surnames

kable_report(surname, NULL)

osa_similarity() and lcs_seq_similarity() lead again, but the interesting rows are the next two.

editex_similarity() is the only comparator whose moderate matches (0.84) beat its easy ones (0.83), because the moderate band is where the phonetic variants live. It charges less for a substitution between letters that sound alike, which is exactly the error surnames collect when they are taken down by ear:

CHAN/CHEN, WANG/WONG and HALL/HILL all collapse to one code. That makes phonetic codes excellent blocking keys – generous, cheap, and they bring the right pairs into consideration – and poor deciders. sec-uc-link compares the codes by how aggressively they merge; use one to generate candidates and a similarity to score them.

The hard matches here are the other familiar surname problem: SMITH/SMITH-JONES after a marriage, LEE/LEE NGUYEN, VAN DER BERG/BERG. One string is contained in the other, which is a containment question, and the containment-shaped comparators answer it:

contained <- surname[surname$degree == "hard" & surname$match, c("a", "b")]

    tversky_in     = round(tversky_index(contained$a, contained$b, q = 3,
                                         alpha = 1, beta = 0), 2),
    fuzz_token_set = round(fuzz_token_set_ratio(contained$a, contained$b) / 100, 2),
    smith_waterman = round(smith_waterman(contained$a, contained$b), 2)
)

tversky_index(alpha = 1, beta = 0) asks only “how much of a is in b?” and so ignores the words b has added. Note that this makes it directional, which the VAN DER BERG/BERG row shows: the extra words are on the a side there, and the score collapses to 0.20. When either side may be the fuller one – which is the normal case across two files – score both directions and keep the larger:

both_ways <- pmax(
    tversky_index(contained$a, contained$b, q = 3, alpha = 1, beta = 0),
    tversky_index(contained$b, contained$a, q = 3, alpha = 1, beta = 0)
)
data.frame(contained, containment = round(both_ways, 2))
               a           b containment
13         SMITH SMITH-JONES        1.00
14           LEE  LEE NGUYEN        1.00
15  VAN DER BERG        BERG        1.00
16 WOJCIECHOWSKI      WOJCIK        0.75

Containment costs precision: tversky_in is near the bottom of Table tbl-surname overall, because it also rates MARTIN/MARTIN JR and SINGH/SINGHA highly – which is the whole trade in one row. So score both: a high osa_similarity() or a high containment score, with the reason recorded, beats one blended number nobody can audit.

7.6 Addresses

kable_report(address, NULL)

The ranking inverts. The q-gram set metrics and the containment score lead; jaro_winkler() is second from last, and the edit similarities that won on names are mid-table. Addresses break the assumptions those metrics make:

  • Length varies enormously between two renderings of the same address (9 KING ST versus 9 KING STREET WEST END BRISBANE QUEENSLAND). An edit similarity divides by the longer length, so a true match is punished for the detail one side happens to carry. tversky_in scores those pairs 1.00 (tp_hard) precisely because it does not.
  • The decisive difference is tiny. 12 SMITH ST versus 21 SMITH ST is two characters out of eleven, and a different house. Every comparator in the table scores the hard non-matches above 0.4, and the four best separators score them 0.69–0.84. There is no threshold that keeps those out.
  • Tokens move. LEVEL 3 100 QUEEN ST and 100 QUEEN ST LEVEL 3 are one address, which rewards the token and q-gram comparators and penalises anything positional, prefix_similarity() worst of all (0.11 on moderate matches).

So the first thing to do with an address is not to pick a better comparator; it is to stop comparing the whole string. Two moves fix most of it. Standardise the vocabulary, then compare components separately, exactly where an exact comparison belongs:

street_types <- c(
    STREET = "ST", ROAD = "RD", AVENUE = "AVE", CRESCENT = "CRES",
    PARADE = "PDE", DRIVE = "DR", COURT = "CT", PLACE = "PL",
    HIGHWAY = "HWY", LANE = "LN", TERRACE = "TCE", SAINT = "ST"
)
std_address <- function(x) {
    freplace_tokens(fsquish(fupper(ascii_fold(x))),
                    names(street_types), street_types)
}
house_number <- function(x) fextract("^[0-9]+[A-Z]?", fsquish(fupper(x)))

hard_cases <- address[address$degree == "hard", ]
data.frame(
    hard_cases[c("a", "b", "match")],
    no_a  = house_number(hard_cases$a),
    no_b  = house_number(hard_cases$b),
    agree = house_number(hard_cases$a) == house_number(hard_cases$b),
    tversky_in = round(tversky_index(std_address(hard_cases$a),
                                     std_address(hard_cases$b),
                                     q = 3, alpha = 1, beta = 0), 2)
)

7.7 Cost is not the deciding factor

All nineteen comparators are compiled and parallel, so the choice can be made on accuracy alone. On 200,000 pairs of surnames:

set.seed(1)
pool <- c("SMITH", "SMYTH", "JONES", "NGUYEN", "PAPADOPOULOS", "OBRIEN",
          "WILLIAMSON", "CHAUDHRY", "SZCZEPANSKI", "LEE")
left  <- sample(pool, 2e5, replace = TRUE)
right <- sample(pool, 2e5, replace = TRUE)
timings <- sapply(comparators, function(f) system.time(f(left, right))[["elapsed"]])
cost <- data.frame(comparator = names(timings), seconds = round(unname(timings), 3))
knitr::kable(cost[order(cost$seconds), ], row.names = FALSE,
             col.names = c("Comparator", "Seconds"))

The spread between the cheapest and the dearest is a few hundredths of a second over 200,000 pairs. Candidate generation, not scoring, is where a linkage spends its time (sec-benchmarks), so score two or three comparators per field and keep the columns – it costs almost nothing and makes a clerical reviewer’s job far easier than one blended number.

7.8 What to use

Field, and what goes wrong in it Use Why
Given name, typos and dropped letters osa_similarity() best AUC here; counts a transposition as one edit
Given name, where longer names are different people (ALAN/ALANA) osa_similarity(), or jaro_winkler(p = 0) length-sensitive; no prefix bonus to exploit
Given name, typos in the first letters jaro_winkler() the prefix bonus earns its keep
Given name, nicknames and short forms freplace_tokens() first, then score not a string-distance problem
Given names in one field, reordered jaro_winkler_tokens(), monge_elkan() align whole words in any order
Surname, taken down by ear editex_similarity() cheaper substitutions between like-sounding letters
Surname, general scoring osa_similarity(), lcs_seq_similarity() best AUC here
Surname, candidate generation soundex(), double_metaphone(), nysiis() perfect recall on easy and moderate pairs; far too generous to decide with
Surname, double-barrelled or added names tversky_index(alpha = 1, beta = 0), fuzz_token_set_ratio() containment, ignoring what the other side adds
Address, whole-string comparison jaccard_index(q = 3), cosine_similarity(q = 3) tolerant of token order, strict about unshared content
Address, one side carrying extra detail tversky_index(q = 3, alpha = 1, beta = 0), smith_waterman() asymmetric: extra material in b is free
Address, reordered tokens fuzz_token_set_ratio() set comparison over words
Address, house number, unit, postcode exact comparison of the parsed component the decisive differences are one character long
Free text, long strings fuzz_token_set_ratio(), cosine_similarity() word sets, not character edits
You need to explain a score edit_ops() returns the edits themselves

7.9 Putting it together

The four pairs below are the hardest kinds in this chapter: two different people whose names look alike, and two matches disguised by a nickname and by abbreviation. One comparator on one field cannot resolve them. The recipe can: standardise, use the comparator that suits each field, compare the decisive component exactly, and let the fields vote.

left_file <- data.frame(
    given   = c("ALAN", "DANIEL", "MICHELLE", "ROBERT"),
    surname = c("BAKER", "THOMSON", "WILLIAMSON", "SMITH"),
    address = c("12 Smith St", "100 Queen St Brisbane",
                "7 Bottlebrush Crescent", "45 St Kilda Rd Melbourne"),
    truth   = c("different person", "different person",
                "same person", "same person")
)
right_file <- data.frame(
    given   = c("ALANA", "DANIEL", "MICHELE", "BOB"),
    surname = c("BARKER", "THOMPSON", "WILLIAMSEN", "SMYTH"),
    address = c("21 SMITH ST", "100 QUEEN ST MELBOURNE",
                "7 BOTTLEBRUSH CRES", "45 SAINT KILDA ROAD MELBOURNE")
)

std_name <- function(x) {
    freplace_tokens(fsquish(fupper(ascii_fold(x))), names(nicknames), nicknames)
}
prepare <- function(d) {
    d$given   <- std_name(d$given)
    d$address <- std_address(d$address)
    d$no      <- house_number(d$address)
    d
}
left_std  <- prepare(left_file)
right_std <- prepare(right_file)

scored <- rLink(
    left_std, right_std,
    pairs   = data.frame(x_index = 1:4, y_index = 1:4),
    compare = list(
        given   = osa_similarity(given),
        surname = editex_similarity(surname),
        address = tversky_index(address, q = 3, alpha = 1, beta = 0),
        number  = (function(x, y) as.numeric(!is.na(x) & !is.na(y) & x == y))(no)
    ),
    keep = c("given", "surname", "truth")
)
scored$decision <- ifelse(
    scored$number == 1 & pmin(scored$given, scored$surname, scored$address) >= 0.75,
    "match", "non-match"
)

7.10 Running this on your own data

The ranking in this chapter is the ranking for these pairs. Fields differ, collection methods differ, and the only reliable way to choose is to grade a few dozen pairs of your own and re-run the tables:

  1. Take a sample of candidate pairs from your own blocking – from rLink() with compare = NULL, say – and label them, including the awkward ones. A hundred pairs per field is enough to separate the comparators; it is not enough to tune a threshold to three decimal places.
  2. Grade each pair easy, moderate or hard, and keep the kind column. When a comparator does badly, the kind of the pairs it fails on tells you what to standardise.
  3. Swap your data frame into report() above. Nothing else in the scaffolding is specific to these examples.
  4. Read margin and the moderate columns, not the top line. A comparator with a high AUC and a thin margin is one bad batch of data away from failing.

sec-uc-link puts the chosen comparators into a full linkage, and sec-theory explains what each one computes.
